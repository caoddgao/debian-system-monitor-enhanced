# 硬件读取说明 / Hardware readings

Temperature colors are UI warning settings, not official hardware safety limits. CPU and both GPUs use green below 50 °C, yellow from 50 °C, red from 70 °C. DDR5 DIMMs use 50/65 °C, Samsung NVMe uses 45/60 °C, and other disks use 40/50 °C boundaries. Capacity and CPU load use 70/90% visual pressure levels. High GPU utilization uses the theme accent instead of a danger color. Frequency, power, fan, network, and disk activity use the theme accent without invented safety thresholds. N/A is neutral. If device specific temperature limits become available from its sensor or manufacturer, record them separately before changing these UI thresholds.

Hardware collection is in [`gnome-system-monitor-48.1/src/hardware.cpp`](gnome-system-monitor-48.1/src/hardware.cpp), separate from GTK UI code. A background worker samples only while Resources is active, every 5 seconds; NVML is used through `libnvidia-ml.so.1`. NVMe temperatures come from sysfs. ATA disk temperature comes from UDisks' cached SMART temperature property, converted from Kelvin to Celsius and matched to the existing block device; the app does not request a SMART refresh or wake a sleeping disk. The ATA value may update less often than the UI sampling interval. The application does not change driver settings, fan curves, power limits, or clocks.

Memory type and configured transfer rate come from udev’s cached SMBIOS configuration via libsystemd (>=251). The host reports `DDR5 5200`; the module rating is 5600 MT/s. The displayed configured rate is not a live clock reading. Empty slots are skipped, unavailable values show N/A, and differing module configurations are listed separately. Builds with systemd support disabled show N/A for this field.
